## BACKGROUND

This work is the GIAB whole genome assembly-based small and structural variant
benchmark sets, released as v5.0q. Previously, GIAB whole genome benchmark sets
were generated by integrating variant callsets generated using mapped reads as
input. Challenging genomic regions were inaccessible using these mapping-based
approaches. Improvements to DNA sequencing and genome assembly methods have made
generating high quality whole genome diploid assemblies possible. Previous
assembly-based approaches were used in a targeted manner to characterize
difficult regions of the genome such as the MHC
(<https://doi.org/10.1038/s41467-020-18564-9>), challenging medically relevant
genes (<https://doi.org/10.1038/s41587-021-01158-1>), and more recently Tandem
Repeats (<https://doi.org/10.1038/s41587-024-02225-z>), and the XY chromosomes
(<https://doi.org/10.1038/s41467-024-55710-z>). Using an assembly-based approach
to generate variant benchmarks allows for the characterization and inclusion of
challenging genomic regions and variant types previously excluded from GIAB
benchmark sets. For development of assembly-based variant benchmarks, we made a
snakemake pipeline for automating the generation of assembly-based benchmarks,
DEvelopment FRamework for Assembly-Based Benchmark (DeFrABB). Through a parallel
effort, the T2T consortium is working towards creating a near-perfect diploid
assembly for the GIAB HG002 reference material (NIST RM 8391), aspirationally
called the T2T Q100 project (<https://github.com/marbl/hg002>,
<https://doi.org/10.1101/2025.09.21.677443>). These variant benchmarks are based
on the V1.1 release of the T2T HG002 Q100 assembly. As these benchmark sets are
our first whole genome assembly-based variant benchmarks we appreciate and
welcome feedback on the benchmarkset, particularly potential errors in the
benchmark set or recommendations for improving usability.

### Data Usage

The draft benchmark VCF and BED files are intended to be used as a pair to
benchmark accuracy of small and structural variant calls. Separate VCFs are
provided for small variant and SV benchmarking. Both VCFs contain the same
variant calls; the stvar VCF additionally includes decomposed multiallelic and
annotated SVs. Structural variants are excluded from the small variant benchmark
regions and their inclusion in the benchmark calls will not affect small variant
benchmarking. Inclusion of small variants in the benchmark VCF used for SVs can
aid in matching variants with different representations. Benchmarking variant
calls is a complex process. For small variants we recommend following the best
practices for benchmarking small variants published in 2019 by the Global
Alliance for Genomics and Health (GA4GH) Benchmarking Team
(<https://rdcu.be/bqpDT>). For structural variants, unlike our previous
benchmarks, this draft benchmark does not exclude complex SVs, so we recommend
using SV comparison tools developed to accurately compare complex variants, such
as truvari with the refine step (<https://github.com/ACEnglish/truvari>,
<https://doi.org/10.1186/s13059-022-02840-6>), hap-eval
(<https://github.com/Sentieon/hap-eval>), vcfdist
(<https://github.com/TimD1/vcfdist>,
<https://doi.org/10.1186/s13059-024-03394-5>), or aardvark
(<https://github.com/PacificBiosciences/aardvark>,
<https://doi.org/10.1101/2025.10.03.680257>). While in our experience these
tools correctly handle these comparisons in most cases, we recommend curating a
subset of putative FPs and FNs to evaluate if they are an error in your
comparison callset or the benchmark, or just different representations of the
same variant.

#### Benchmarking small variants using hap.py

- recommend using the
  [rtg-tool vcfeval](https://github.com/RealTimeGenomics/rtg-tools) comparison
  engine
- use `--gender male` as hap.py does not correctly predict sex and assumes X
  variants are diploid
- recommend using
  [GIAB v3.6 stratifications](https://ftp-trace.ncbi.nlm.nih.gov/ReferenceSamples/giab/release/genome-stratifications/v3.6/)
  (<https://doi.org/10.1038/s41467-024-53260-y>)

```bash
hap.py \
    --engine vcfeval \
    --gender {male for HG002} \
    -r {reference fasta} \
    -f {benchmark regions bed} \
    --stratification <stratification tsv> \
    -o {output prefix} \
    {benchmark variants vcf} \
    {comparison vcf}
```

#### Benchmarking structural variants using truvari refine

- truvari compares SVs with different representations using the --refine option

```bash
truvari bench \
    -b {benchmark variants vcf} \
    -c {comparison vcf} \
    -o {output dir} \
    -f {reference fasta} \
    --includebed {benchmark regions bed} \
    --pick ac \
    --passonly \
    -r 2000 \
    -C 5000 \
    --refine
```

While `truvari refine` is able to correctly compare complex variants with
different representations, it changes the variant representations, making it
more challenging to determine whether a specific variant call in the comparison
VCF was classified as TP/FP or which benchmark variants were FNs. To determine
which variants in the original VCFs were incorrect, users may want to use the
`truvari bench` output. However, for truvari bench, variants with `ALT=*` are
often incorrectly categorized, so users are encouraged to filter these variants
from the benchmark VCF prior to benchmarking with truvari bench.

The `ALT=*` variants can be filtered using the following command:

```sh
bcftools view -e 'ALT="*"' -Oz -o benchmark_noAltAst.vcf.gz benchmark.vcf.gz
```

### LIMITATIONS

These benchmark sets were generated using a new assembly-based approach which is
under active development, therefore benchmarking results generated using these
benchmarks should be carefully evaluated. While we try to exclude regions with
complex structural variation, some regions likely remain where the assembly
could be aligned to the reference in a different way. As these benchmark sets
are a work in progress we appreciate and welcome feedback, particularly
potential errors or recommendations for improving usability.

## METHODOLOGICAL INFORMATION

Initial diploid assembly regions and variant calls were generated using the
[defrabb pipeline](https://github.com/usnistgov/defrabb) that uses
[dipcall v0.3](https://github.com/lh3/dipcall) to align the diploid assembly to
a reference genome with minimap2 (mm2), and then call variants and identify
regions covered by both haplotypes. To increase mapping around structural
variants and the MHC region, the `-z` parameter used by mm2 was modified from
default to `-z200000,10000`.

The initial diploid assembly regions and variant calls were refined to generate
the draft small variant and structural variant benchmark sets. The refinement
steps included exclusion of genomic regions with either systematic assembly or
assembly-based variant calling errors as well as regions of the genome that
present challenges related to variant representation and comparisons. In
particular, we started with regions with a 1:1 alignment between each assembled
haplotype and the reference (except X&Y) and then excluded gaps in the assembly
and their flanking sequences (rDNA sequences for CHM13), as well as any large
repeats (satellites, tandem repeats

> 10kb, and segmental duplications) that have a break in the assembly to
> reference alignment on either haplotype. Segdups and satellites within 40kb
> were merged before checking if the assembly has any breaks in the alignment
> inside the repeat regions, to also exclude nearby satellites and segdups if
> there is a break in the alignment inside a satellite or segdup. Primarily
> because we exclude regions inside inversions even if they are very large, some
> regions included in v4.2.1 are excluded in v5.0q. We also exclude regions
> affected by SVs from the small variant benchmark bed. Additional exclusions
> were applied for known dipcall bugs, discrepancies between PAV and dipcall
> callsets, as well as HG002 assembly errors and mosaic variants. The HG002
> assembly errors were corrected in v1.1 of the Q100 and will likely be included
> in the next version of the benchmark.

**Dependencies:** defrabb pipeline (<https://github.com/usnistgov/defrabb>),
which utilizes dipcall (<https://github.com/lh3/dipcall>) for assembly based
variant calling, and Truvari (<https://github.com/ACEnglish/truvari>) for SV
annotations.

**Quality Assurance:** These benchmarks have been compared to numerous small and
structural variant call sets that have been previously identified as
high-quality as well as external evaluations. The comparison results from both
internal and external evaluations indicate these benchmarksets can be used to
reliably identify errors in comparison callsets.
